# 答辩问答库（30 题预案）

> 用法：每题含【答】（3-5 句参考回答）与【忌】（不要说什么）。
> 答辩前通读两遍，不求背诵，求方向不乱。

---

## 一、技术类（10 题）

**Q1 为什么用 Flask 不用 Django？**
【答】本系统规模是 12 模块 62 条路由，核心诉求是轻量分层与低成本部署。Flask 的微内核允许我按蓝图自定义工程结构（api/service/model 三层），不被 Django 的 Admin/Form 全家桶绑定；同时家庭部署场景下 Flask 单文件起步、依赖少、启动快。Django 的优势（自带后台、ORM 功能全）对本系统价值有限——后台管理我按需实现了 5 个接口。
【忌】贬低 Django（"Django 太烂/太重"）；说"因为教程用的 Flask"。

**Q2 ARIMA 和 ARIMAX 有什么区别？**
【答】ARIMA 是纯自回归：只用价格自身的历史（差分、自回归、移动平均）预测未来。ARIMAX 在此基础上引入外生变量 X——我的实现里把玉米价格作为外生变量，理论上捕捉饲料成本向活畜价格的传导（饲料占养殖成本六成以上）。系统两个模型都实现了，前端可切换对比；从回测看 ARIMAX 在置信区间宽度上更收敛，点精度两者都达优秀级。
【忌】背书式定义不给应用；声称 ARIMAX 一定更准（小样本下未必显著）。

**Q3 反推系数 0.38 怎么来的？为什么不是 0.5？**
【答】0.38 是 12 个同日重叠周的"活牛价÷牛肉价"实测均值，剔除一个口径混搭周（本地季报活牛×部级牛肉，比值跳到 0.46）后为 0.3822，标准差只有 0.01。为什么不是 0.5：活牛到牛肉要经过出肉率折损（约 40~45%）和屠宰加工流通成本，所以收购价只有肉价四折左右——外部旁证是农业农村部数据（主产省活牛 28.76÷全国牛肉 74.41=0.3865），和我的实测一致。
【忌】说"试出来的"；回避 0.46 那个异常周（主动讲反而加分）。

**Q4 数据量这么小，预测准吗？**
【答】诚实地说这是本研究的客观约束。地市级周报序列天然就短，我的对策有三：插值转日度增加序列长度、反推补全从 13 周扩到 32 周、选对小样本更稳的经典统计模型而非深度学习。回测 MAPE 0.75% 是真实数据留出法的结果，但我也在论文里如实标注了插值序列回测会系统性偏乐观。随每周爬虫积累，序列会自然变长。
【忌】吹"非常准"；被追问时慌——直接说 MAPE 口径和局限性。

**Q5 为什么用 MySQL 不用 PostgreSQL？**
【答】本系统是单机读多写少的典型场景，MySQL 8.0 完全胜任且有三个实际原因：家庭电脑上部署运维资料最多；utf8mb4 对中文和生僻字符支持成熟；学校教学环境以 MySQL 为主，家人未来找其他人维护时门槛低。PostgreSQL 的分析函数和 JSON 优势在本系统没有用武之地，选型上"够用且好维护"优先于"功能更强"。
【忌】说"MySQL 更好"（绝对化）；承认自己没用过 PostgreSQL 却找技术借口。

**Q6 前端为什么选 Vue 不选 React？**
【答】两个实际原因：一是生态匹配——我要做移动端家用版和桌面分析版两套界面，Vue 有现成的 Vant（移动）和 Element Plus（桌面）组件库，风格统一、开箱即用；二是组合式 API 的学习曲线平缓，适合一个人完成全栈。React 技术上完全能实现同样的系统，选型差异在这里不影响论文贡献。
【忌】"React 太难"（显得逃避）；虚空对比性能。

**Q7 数据源不够多怎么办？**
【答】我系统性地评估了 14 个候选源，结论写进了数据源地图文档：省级三大厅局被 WAF 拦截（412 JS 挑战），这个是客观限制；市州部门站可达且我落地了定西、平凉两个，红牛指数经转载页落地。扩源的路子也铺好了：爬虫框架统一输出标准记录，新源只需加一个 Spider 类和正则；贩子报价（source=dealer）通道也预留了，家人用 Excel 记、我导入——这反而是独家数据。
【忌】抱怨"政府不让爬"；把 WAF 说成无法逾越的技术奇迹。

**Q8 系统能支撑多少并发？**
【答】实际场景是 1~3 部手机加 1 台电脑的家庭局域网访问，Flask 开发服务器（多线程）完全够用。我做过接口性能实测：查询类 50~200ms、预测热跑 3 秒内。如果真要上规模，路径是现成的：docker-compose 里已经编排了 gunicorn 多 worker + nginx 的生产形态，MySQL 4000 行规模加索引后毫秒级，瓶颈会先出现在预测计算的 CPU 上——那可以用预测结果缓存（每日定时预跑落库）解决。
【忌】编一个"支持 XXX 并发"的数字；说"没测过"就结束（要给方案）。

**Q9 数据安全怎么保证？**
【答】分层说：传输层目前是局域网 http（内网 threat model 下可接受），公网部署规划了 Tailscale 组网免开端口；应用层 JWT 鉴权 + bcrypt 密码哈希，登录失败不区分"用户不存在/密码错误"（防用户枚举），家用功能受模式开关保护；数据层价格数据本身非隐私，敏感的只有账本记录，全部按 farm_id 隔离。数据库密码全程环境变量注入，代码库无明文（git 历史可查）。
【忌】吹"https 加密了"（实际没有）；遗漏"不泄露用户存在性"这类细节亮点。

**Q10 有没有考虑过分布式？**
【答】考虑过并有意不做。本系统数据量 4000 行、并发个位数，引入消息队列/微服务只会增加家庭场景的运维负担，违背"家人能用"的设计目标。但我做了面向扩展的解耦：爬虫/预测/预警都是独立幂等任务（APScheduler 调度），天然适合抽成独立 worker；数据层读写分离在 docker-compose 里加一个 MySQL 副本即可。单体是有意识的选择，不是能力缺失。
【忌】"没考虑过"；为显技术强行说"下一步就拆微服务"。

## 二、业务类（10 题）

**Q11 为什么选甘肃牛羊？**
【答】三个原因：产业上，甘肃牛羊存栏全国前列且家庭牧场是主体，价格决策痛点真实；数据上，我逐一验证了本地数据源，定西、平凉畜牧局周报零反爬可稳定抓取，红牛指数提供特色畜种参考价——数据基础成立；个人上，我家就养 50 头黄牛、500 只羊，需求来自真实生产，家用版的每句提示语都经过"我爸能不能看懂"的检验。
【忌】只说"因为我是甘肃人"；空谈乡村振兴不落到具体痛点。

**Q12 和已有的惠农网有什么区别？**
【答】惠农网是交易平台，报价由卖家发布、粒度到品种且混杂（我侦察时确认它有牛犊月龄细分，但没有本地政府监测口径的连续周序列）。我的系统做的是"分析+决策"：以政府周报为底座（口径统一、可回溯两年），加上预测、预警、成本测算——和惠农网是互补而非竞争：家人在惠农网看贩子价，在我系统里看政府基准价并决定何时卖。
【忌】贬低惠农网数据"都是假的"；说"我功能比它多"（平台量级不同）。

**Q13 家庭牧场真的会用吗？**
【答】我在用真实用户验证：系统已部署在家里局域网，我爸手机能访问；写了大白话使用指南（红涨绿跌、"拿不准就截图发儿子"）；考虑了使用成本——打开就是四个大数字，不用记任何操作。当然我不夸大：老一辈的使用习惯需要过渡，所以配了 Excel 记账模板的过渡方案，贩子报价由我爸随手记、我来导入。这是设计给"逐步采用"的系统。
【忌】吹"我爸妈天天用"（未验证的事不说）；说"不会用是他们的问题"。

**Q14 预测不准怎么办？**
【答】三层防线：第一，预测输出永远带置信区间和 MAPE 评级，前端明确标注"预测仅供参考，不构成投资建议"；第二，出栏建议的规则设计为"价格高于成本线就安全"，预测只影响"多赚多少"而不是"亏不亏"的底线判断；第三，预测精度有落库追踪（predict_result 表），精度劣化可见，序列变长后可以换模型重训。
【忌】保证"准确率 95%"；把预测说成决策唯一依据。

**Q15 成本计算的依据是什么？**
【答】日饲料成本是系统按定西最新真实饲料价（玉米 1.17、豆粕 1.65 元/斤）× 饲料配比自动算的，配比可由牧场在成本配置里自定义；利润和盈亏平衡价（总成本÷体重÷2）是透明公式，我在测试里手工验算过（450kg、成本 9000 元 → 保本价 10 元/斤）。需要说明 total_cost 由用户输入——每头牛的购入成本只有养殖户自己知道，系统不猜测。
【忌】把默认配比说成"科学最优"；回避 total_cost 的来源。

**Q16 预警阈值怎么定？**
【答】分两类。成本线类阈值有客观锚：盈亏平衡价（如 10 元/斤）加安全边际，系统当前跑着的规则 A（活牛跌破 14 元）就是这个逻辑——成本线 10 元 +4 元缓冲。波动类阈值参考历史分布（玉米 1.2 元约是两年序列的上沿）。阈值全部可由用户在预警页自定，系统不锁死——因为每个牧场的成本结构不同。
【忌】说阈值是"算法自动学习的"（没有的事）；给不出 14 元的来历。

**Q17 反推数据的可信度？**
【答】三个数字回答：系数本身高度稳定（11 周标准差 0.0102，变异系数 2.7%）；反推值合理性核验过（反推结果 12.8 元/斤落在真实观测区间 11.6~15.2 内）；使用边界严格——只补预测序列、不进统计报表、前端灰色虚线可辨识。诚实地说它是"基于稳定统计关系的估计"，不是观测——所以我把它标记得比什么都清楚。
【忌】说反推数据"也是真实数据"；回避口径混搭周的处理。

**Q18 为什么分牛羊不问猪？**
【答】数据源决定的：我验证过的定西、平凉畜牧局周报体系都含牛羊价与饲料价，而张掖有猪价周报但确认无牛羊价。更根本的是家庭牧场的生产结构——牛羊是多年饲养、单值高的资产（一头育肥牛上万元），出栏时机决策的价值远高于猪（周期短、单值低），预测模型带来的决策改善空间最大。
【忌】"猪肉不重要"（错误且冒犯）；绕开张掖猪价的事实不谈。

**Q19 数据的时效性如何？**
【答】分源说：定西、平凉周报由定时任务每周一上午自动抓取，滞后源站发布约 1~2 天；红牛指数月更（每月 1 日抓）；红牛 9 月期因转载媒体未收录暂缺，收录后重跑脚本自动补入——幂等设计保证了补数零风险。对家庭决策而言，周度时效是匹配的：出栏决策窗口是"天/周"级而非"分钟"级。
【忌】吹"实时数据"（是周更）；隐瞒 9 月期缺口（主动说反而显得诚实可控）。

**Q20 系统维护成本高吗？**
【答】刻意做低了：部署是家庭电脑 + 局域网，零软件成本；日常维护就是每周看一眼定时任务的日志（爬虫失败会留痕），我做了幂等设计所以重跑无害；数据自动积累无需人工。真正需要人的是两件事——月度核对一下 Excel 记录导入、以及源网站改版时修爬虫（正则集中在单文件，我留了完整的数据源地图和七轮工作报告，接手者可依图施工）。
【忌】说"零维护"（不诚实）；把爬虫脆弱性说成无解。

## 三、创新点类（5 题）

**Q21 你的创新点是什么？**
【答】三个，按重要性排序。一是双标记数据体系：source（六种来源）× is_sample 正交标记，让真实观测、反推衍生、贩子报价、示例数据在一张表共存且默认互不污染——这是小型数据系统的数据治理实践。二是活畜价格反推补全：用实测系数（三重验证）把 13 周观测扩展成 32 周可建模序列，解决了"源站发布不稳定"的真实数据工程问题。三是轻量双端适配：一个后端用模式开关同时服务研究者和养殖户，后者拿到的是"现在能不能卖"的人话建议。
【忌】把"用了 ARIMAX"本身当创新（是应用不是创新）；罗列五六个稀释重点。

**Q22 和同类系统比有什么优势？**
【答】对比三个参照：比政府发布渠道，我做了整合与口径统一，并把数据变成决策建议；比商业化牧场管理系统（重生产管理），我补上了"价格—预测—出栏决策"这条缺失的链路；比学术预测论文（常有数据无系统），我有真实家庭在用的完整落地——188 条真实数据、部署运行中、家人指南。一句话：真实数据 + 完整系统 + 实际使用，三者的交集是稀缺的。
【忌】声称"全网首创/国内领先"（无检索支撑）；逐条贬低他人系统。

**Q23 论文工作量够吗？**
【答】可以量化：七轮迭代开发，git 提交记录完整；后端 12 模块 62 路由约 X 千行（答辩前统计填入），前端两套 Vue 工程；数据工程上侦察 14 源、落地 3 个爬虫、建立 188+40 条标注数据库；方法上实现反推补全并做了系数核实实验；测试 28 项自动化 + 七轮人工验收；文档上七轮工作报告、数据源地图、使用指南、部署指南齐备。这些都在仓库里可查证。
【忌】只说"我很努力"；给不出可验证的量化。

**Q24 你在项目中遇到的最大困难是什么？**
【答】数据获取。省级站群全部被 WAF 拦截，一度没有可用数据源；我花了四轮侦察换打法——放弃省级、转向市州部门独立站，定西站靠分析 CMS 的数据代理接口拿到 XML 列表绕过 JS 渲染，红牛指数靠东方财富搜索接口定位转载页。这个过程教会我：数据工程项目的一半工作是在约束下找到可行路径，而且要"宁缺毋滥"——张掖 18 条猪价因为品类不符我宁可不入库。
【忌】说困难是"代码 bug 调不出来"（显得浅）；说"没遇到什么困难"。

**Q25 这个题目还能怎么深入？**
【答】三个方向。数据：引入青海牦牛/藏羊指数补齐特色畜种，接入贩子报价流形成"政府基准+市场实际"双轨价格。模型：序列积累到百点以上后做 SARIMA 季节项、多外生变量和区间校准的对比实验，甚至引入机器学习方法做基准对照。系统：Excel 报价一键导入、移动端推送预警、面向村合作社的多牧场权限——让系统从"一家的工具"变成"一片区域的公共服务"。
【忌】漫无边际列十项；说"就这样挺完善了"。

## 四、刁难类（5 题）

**Q26 这个系统是不是 AI 帮你写的？**
【答】我用了 AI 辅助，方式类似用更聪明的搜索和结对编程：架构设计、技术选型、每一轮的决策是我定的，代码我来审查和调试，出现了问题（比如预测回测形状 bug、口径混搭周）是我自己定位修复的。衡量这一点有个简单办法——您可以就任何一处实现细节提问，比如双标记体系为什么这么设计、系数 0.38 怎么剔除异常周，我可以现场推演。AI 是工具，工程判断和验收是我的。
【忌】坚决否认用过 AI（如果用了，撒谎风险更大）；反问"老师您觉得呢"。

**Q27 如果网站（数据源）挂了怎么办？**
【答】分层回答。源站挂：爬虫逐源 try/except，单源失败不影响已有数据和系统运行，恢复后重跑幂等补齐——定西 9 月就有两周文章 404/空正文，系统照常，日志留痕。我的系统挂：家用场景重启脚本一条命令（家人指南里写了"打不开先看主机开没开"）；重要数据在 MySQL 有周日备份任务位。不可抗力：历史数据已入库 188 条，即使源站永久关闭，存量分析不受影响。
【忌】"没想过"；承诺"永远不会挂"。

**Q28 数据被爬走了怎么办（你的数据安全/版权）？**
【答】两个层面。数据版权：我抓取的是政府公开信息和媒体转载页，遵守了 3 秒间隔和研究性 UA 标识，用于个人研究毕设，论文里注明了来源；政府数据本身就是公开属性。我的系统被爬：本系统只在家庭局域网，不暴露公网（规划中的 Tailscale 也是私网组网）；即便被爬，price_data 里的数据本就来自公开渠道，真正的私产是账本记录——那部分有 farm_id 隔离和登录鉴权。
【忌】把公开政府数据说成"我的数据版权"；说"加了反爬"（没有也不必要）。

**Q29 你觉得这个系统有什么不足？**
【答】主动说四个。数据覆盖不足——只有定西/平凉两口，牦牛藏羊没有政府口径源；序列仍短——活牛真实观测才 13 周，反推补全只是过渡方案，系数需随积累复核；预测验证深度有限——没有做区间校准（coverage 检验）和跨市场外推验证；工程上单体架构、无自动化部署流水线。这些不足和对应的改进方向都写进了论文第 7 章。
【忌】说"没什么大不足"；不足列一堆不给对策。

**Q30 如果重做一次你会怎么做？**
【答】三件事。先数据后功能：第一周就把所有数据源验证完再动手写代码（我实际是边做边发现省级源全被拦，返工了路径）。更早引入家人参与：早期就该让父亲试用提需求，有些"想当然"的界面后来被证明老人不会用。预测部分更早做严谨的实验设计：预先定义好基线（朴素法/季节均值）和评价指标，避免事后补实验。架构本身我不后悔——单体对这个场景就是对的。
【忌】"会换个题目/用别的技术栈重写"（否定自己的工作）；说"不会有什么不同"。
